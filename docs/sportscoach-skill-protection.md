# Sportscoach source-owned skill protection

## What is enforced

`deploy/sportscoach-skill-protection.conf` is a user-service drop-in for **hermes-gateway-sportscoach.service only**. `PrivateUsers=yes` enables a private mount namespace in the user service. Its `ReadOnlyPaths` protects the three installed canonical skill trees, their ownership manifest and the canonical repository's knowledge tree. Ordinary writes, creates, renames and deletions through tools or child processes encounter the filesystem's read-only enforcement. Other profiles, task state, temporary import data and new skill/proposal locations remain writable.

The service's `ExecStartPre` runs the canonical installer verifier. Startup fails rather than silently accepting mismatched installed/source bytes, stale or missing manifest metadata, retired managed remnants or unowned discoverable supporting files. Verification is read-only. Installation preflights everything before effects and preserves unknown/local content for source reconciliation.

This is scoped filesystem protection, not a hostile same-UID security sandbox: an operator or process outside the service namespace can deliberately edit installed content or change the service. Do not claim it prevents every privileged/alternate-service write. The existing daily monitor must still compare source/install/manifest, current policy and the active namespace. Do not add a second repair cron or make the monitor mutate source.

## Source-owned profile capabilities

`deploy/sportscoach-profile-policy.json` owns the domain toolset and skill-visibility contract. CLI, Telegram, Discord, API, Home Assistant and any already-configured platform receive the same useful domain surface: retrieval, calculations, files/proposals, memory, skills, research, messaging and authorized voice. It removes generic delegation, cron creation, desktop control, Discord administration, Kanban, Spotify and image generation; disables coding-context injection; stages new skill writes for review; and hides the conflicting generic Hermes-administration, desktop and generic SQLite/development skills. This is not a hostile shell sandbox: terminal and calculation tools remain useful, and the native read-only knowledge boundary remains necessary.

The current AlphaRunner trio and the voice repository's Sportscoach Alexa guidance stay available. No persona, model/provider, credential, channel routing, database, confirmation deadline or unrelated profile is changed by this policy. Existing intentional restrictions are retained; a restriction that conflicts with required domain tools/skills fails closed instead of being silently undone.

After exact-head GitHub approval and release to clean remote main, apply through the supported configuration editor (not a direct config write):

```bash
EDITOR='/home/john/projects/alpharunner.workspace/alpharunner/scripts/sportscoach-profile-policy-editor' hermes --profile sportscoach config edit
/home/john/.hermes/hermes-agent/venv/bin/python scripts/sportscoach_profile_policy.py --verify
```

`EDITOR` must be a **single executable wrapper path**, not an interpreter/script/arguments command string: installed Hermes invokes `[editor, configfilename]` without shell splitting. The source wrapper must retain executable mode **100755**. It accepts exactly one config filename and invokes the pinned `/home/john/.hermes/hermes-agent/venv/bin/python` interpreter with the sibling policy script's `--editor` callback. Do not install or activate this worktree directly; the example uses the canonical released source path. The regression runs the actual installed `edit_config` function extracted by AST in isolated `HOME`/`HERMES_HOME`, mocking only managed-state and config-path boundaries; subprocess, wrapper and callback are real. This integration test explicitly skips on CI hosts without installed Hermes.

Approved legacy-bundle migration: only exact aliases enumerated in `approved_legacy_bundles` in the source policy (optionally accompanied by native extras or `no_mcp`) may be replaced by the domain allowlist. This includes broad client bundles and the exact stale Teams/Google Chat template aliases observed in the existing profile; those two are not claimed to be current core-defined bundles. Their migration is explicitly included in this source review, not inferred from a `hermes-*` prefix. This is an intentional reviewed migration, not permission to broaden arbitrary selections. Plain lists may narrow only when they already contain **every** policy native toolset. Empty/narrow lists, malformed selections, unsupported bundles that do not contain that complete native set, and explicit MCP selections fail closed without writing. These rules apply both to top-level `toolsets` and all existing platform selections; missing selections receive policy defaults. The policy includes `no_mcp` everywhere to disable automatic discovery of globally enabled MCP servers. An existing `no_mcp` restriction is never removed. Explicit MCP server/tool selections require a separate source-policy review; they are never silently dropped or expanded, even alongside an approved bundle. Unknown extra names are rejected as well, including bare MCP server names without an `mcp` prefix; only source-declared native toolsets and approved migration aliases/extras may be narrowed. `approved_retired_native_toolsets` records the existing Discord native group retirement explicitly; channel delivery remains under messaging/platform configuration.

Required skills must not appear in `skills.disabled` or `skills.platform_disabled` for any supported/already-configured platform. Malformed platform-disabled maps/lists are rejected. Unrelated restrictions and unknown configuration fields remain untouched. Both convergence and read-only `--verify` reject these conflicts even when all required skill files are correctly installed.

The callback accepts only the Sportscoach config path, makes a private byte-preserving backup, preserves unrelated configuration, refuses an observed concurrent change and verifies atomic readback. Install the updated unit only after config verification succeeds. Its additional startup preflight rejects profile-policy drift; its read-only scope now also covers the source-owned installed Sportscoach Alexa guidance and that profile's voice-source knowledge. Default/DJ profiles remain outside this service namespace.

Check live tool schemas and skill discovery separately after the authorized Sportscoach restart; saved YAML is not activation. The existing monitor should compare the declared JSON fields with profile configuration and actual unit mounts, reporting names/booleans rather than secret config values. A pending learning proposal is an intentional writable artifact, not active installed drift. No scheduler repair or second cron is introduced.

## Learning remains available

Sportscoach saves proposed improvements under `~/.hermes/profiles/sportscoach/state/skill-proposals/`, with current evidence and the owning source path. Reconcile useful knowledge in a sibling AlphaRunner worktree, run the gates and independent review, publish/merge with required authorization, then install from clean released main. Do not bypass a read-only refusal with a shell, another tool or service. This protection does not erase previously loaded conversation text; current reference loading and conversational judgment are separate evidence.

## Release and activation

1. Run `pnpm test:run`, `pnpm typecheck`, `pnpm lint` and `python3 -B -m unittest discover -s scripts -p 'test_*sportscoach*.py' -v`. Hosted CI runs these Python regressions too; Vitest guards the CI invocation as well as current-only references. Runtime analysis-reference tests must resolve current mandatory sources, not merely prove Garmin transport.
2. Preserve installed-only knowledge and back up exact pre-change bytes. A divergent target is not automatically stale. Verify source, installed inventory and manifest; migrate reviewed differences explicitly, never disable the installer guard. Install only released main using `python3 -B scripts/install-sportscoach-skills.py --install`, then `--verify`.
3. Create the profile's writable `state/skill-proposals` directory. Install the released drop-in to `~/.config/systemd/user/hermes-gateway-sportscoach.service.d/skill-protection.conf` and byte-compare it with source. Reload user systemd metadata, then use the supported authorized Sportscoach gateway restart. Respect any tool approval denial; never route around it.
4. Correlate the new MainPID with **actual `/proc/<pid>/mountinfo` read-only mount options** for every declared path. `systemctl show` alone proves configuration, not activation. Check startup verification succeeded and messaging adapters connected. Use a controlled transient service with the same native properties to prove writes/creates/renames/deletes are blocked while reads and proposal writes work; do not mutate health rows or perform unsolicited playback.
5. Verify the real profile skill loader loads current references and rejects retired ones. Exercise ordinary read-only Garmin retrieval, verify the complete source/install/manifest vector again, and confirm clean local main equals remote main. Record whether activation is verified, pending or denied; transport success alone never closes the whole migration.

The regression suite intentionally uses temporary fixtures. The native namespace behavior requires a separate real-host probe; CI static unit tests do not pretend to prove the running service loaded the drop-in.
