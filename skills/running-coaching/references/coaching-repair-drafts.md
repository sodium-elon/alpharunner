# Draft-only coaching repairs

Use when the user authorizes repair drafts, not application writes. This is a review artifact workflow, not an import, reassignment or database repair.

## Scope and evidence

1. Recover the exact authorized run/date/activity/shoe tuples from the latest request. A repeated preserved task list is continuity, not permission to restart or expand scope. Use the existing state directory and write only the requested draft artifact. Do not modify DB, code, config, skills, assignments or mileage during the repair task.
2. Load running expertise, rotation, relevant shoe dossier and Stryd guidance. Inspect prepared before-snapshots, analysis features, history and enums. Read the requested benchmark as a structure/style example, never as reusable telemetry or compliance evidence.
3. Project large JSON into bounded summaries before returning tool output. Select sleep duration/score/overnight HRV, wake-up versus post-exercise readiness, deduplicated calendar items, relevant lap rows, and source descriptors if supplied. Never print entire sleep/context objects or time series. If output truncates, retrieve only the missing fields; do not assume omitted evidence was reviewed.
4. Calculate strictly preceding 7/14/28-day counts/load, excluding the target and subsequent runs. Identify incomplete local coverage when the calendar contains additional activity. Choose same-mission/surface/source comparators; same-shoe evidence is especially useful but not proof of causal economy.

## Evidence conflicts and uncertainty

- Actual foreign keys and the latest explicit user shoe instruction outrank stale generated prose. Repair text about the worn shoe without silently changing its assignment. Keep reported comfort and symptoms unknown if absent.
- Research dossiers can reveal historical power-source conflicts in cached summaries. Garmin fallback runs must not become Stryd comparators merely because a history row says Stryd. State the conflict and exclude disputed watts from Stryd trends.
- Deduplicate adaptive calendar entries by date/workout UUID. A completed workout title establishes mission, not the original prescription. Missing duration/intensity targets mean dose compliance cannot be independently certified. Generated reports claiming a percentage are secondary claims, not primary Garmin metadata.
- Prefer actual summaryDTO.directWorkoutComplianceScore or features.garminAssessment when supplied; report this as Garmin's assessment, not independently reconstructed exact-target compliance. Retain user-entered Garmin RPE (raw / 10) and feel separately from algorithmic training load, shoe comfort and current symptoms. Never call supplied primary feedback missing.
- Prepared features may establish a source-labeled power stream and coverage without including raw metricDescriptors. Name that evidence level. Do not present the developer field number, metrics-array index or intrinsic watt label as freshly verified when those descriptors are absent. Never reuse another run's array mapping. Missing Stryd CP means no CP percentages/zones/RSS.
- Separate executed structure, plan fit and recovery risk. Wake-up readiness is pre-run context; post-exercise readiness/recovery time is consequence. Unknown current symptoms require a conditional next-session gate, not automatic cancellation.
- Review contaminated runs.notes in full, using bounded slices when needed. Generated third-person authorization paraphrases are not verbatim original user testimony. Preserve genuine user text exactly. Archive the generated report in the evidence snapshot; propose removal in the draft, never execute it under draft-only authority.

## Draft and validation

Keep coaching fields compact and substantive; richer reasoning and provenance belong in evidenceSummary. Include IDs/dates, intended coaching/observation text, explicit proposed notes handling and material evidence gaps. This is a proposal schema, not authorization for automatic application.

Validate against the actual repository enums and existing constraints, not invented permissive limits: coaching fields <=800 characters each, total <=2000 before the short provenance suffix, shoe-observation notes <=500. Aim 120–180 words across keyPositive/keyConcern/recommendation; report the actual word count and review deviations rather than silently declaring an arbitrary length check sufficient. Validate exact authorized tuples and snapshot identity, numeric activity IDs, UUID syntax, allowed notes actions, and preserved original text.

Parse the sole artifact from disk after writing; read back each run's fields and measured lengths. Record successful checks only when exercised. Finish with the artifact path, draft-only status, significant uncertainty and unchanged scope. Do not claim raw telemetry, live lookups or exact compliance were verified if only prepared snapshots were inspected.
